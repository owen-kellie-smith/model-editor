# Copilot Instructions for model-editor

## Project Overview

**model-editor** is a single-page web application for parsing, validating, and editing large declarative models stored in XML. It runs entirely in the browser with no build step required, using vanilla JavaScript ES6+ modules.

## Key Technologies & Architecture

- **Frontend**: Vanilla JavaScript (ES6+), no frameworks
- **XML Processing**: `@xmldom/xmldom` and `xpath` libraries
- **Testing**: Vitest with jsdom
- **Visualization**: Viz.js for dependency graphs
- **Deployment**: GitHub Pages from `docs/` directory
- **Philosophy**: Zero-build architecture - all code runs directly in the browser

## Project Structure

```
docs/                    # Application source (served via GitHub Pages)
  index.html            # Main UI entry point
  src/
    app.js              # Application entry
    ui.js               # DOM references
    applications/       # Feature modules
    domain/             # Core business logic
      model.js          # Model validation
      language.js       # Language parsing
      variableCrud.js   # CRUD operations
      graphRelations.js # Dependency graphs
      graphviz.js       # DOT format generation
      serialize.js      # XML serialization
    utils/              # Helper utilities
    format/             # Error handling
  styles/               # CSS
  examples/             # Sample XML files
tests/                  # Vitest test suite
```

## Core Concepts

### Variable Definition Types
- **expression** - Mathematical formula using other variables/functions
- **constant** - Simple constant value
- **table** - Array of values indexed by position
- **tableLookup** - Value lookup from a table
- **piecewise** - Conditional definitions with multiple branches

### Key Features
- XML model parsing and validation
- Language function definitions with arity constraints
- Circular reference detection
- Dependency analysis (incoming/outgoing variables)
- CRUD operations for variables
- Interactive dependency graphs

## Development Guidelines

### Code Style & Standards

1. **No Build Step**: Do NOT suggest adding bundlers, transpilers, or preprocessors
   - Keep all code ES6+ modules that run directly in browser
   - Avoid npm dependencies in runtime code
   - Only use npm for dev dependencies (testing, etc.)

2. **Vanilla JavaScript**: 
   - No frameworks (React, Vue, etc.)
   - Direct DOM manipulation
   - Modern ES6+ syntax

3. **Testing**:
   - Use Vitest for all tests
   - Tests located in `tests/` directory
   - Test coverage maps to requirements R1-R10
   - Include test fixtures in `tests/fixtures/`

4. **XML & DOM**:
   - Use `@xmldom/xmldom` for XML processing
   - Use `xpath` for XML queries
   - Validate XML structure in model and language imports

5. **Error Handling**:
   - Provide contextual error messages
   - Include line numbers and element references
   - Don't allow partial state on invalid input

### When Helping with Issues

1. **Bug Fixes**: 
   - Identify the failing test or requirement
   - Preserve all existing validation constraints
   - Maintain zero-build philosophy

2. **New Features**:
   - Map to requirements R1-R10
   - Add corresponding tests before implementation
   - Ensure dependency analysis works correctly
   - Update documentation and examples

3. **Performance**:
   - Keep DOM operations efficient
   - Graph generation should handle large models
   - Minimize XML processing overhead

## Testing Requirements

Run tests with: `npm install && npm test`

Each requirement (R1-R10) has corresponding test files:
- `language.test.js` - R1, R2
- `model.test.js` - R3, R4, R5, R6, R7, R8
- `graphRelations.test.js` - R9
- `variableCrud.test.js` - R10
